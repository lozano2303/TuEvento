# Registros de decisiones de arquitectura (ADR)

Formato: contexto → decisión → consecuencias (Michael Nygard). Un ADR aceptado no se edita; si una decisión cambia, se crea un ADR nuevo que lo reemplaza.

| ADR | Título | Estado |
|---|---|---|
| [001](ADR-001-servicio-y-base-de-datos-independientes.md) | Servicio y base de datos independientes del sistema cliente | Aceptado |
| [002](ADR-002-maquina-de-estados-en-el-dominio.md) | Máquina de estados encapsulada en el dominio | Aceptado |
| [003](ADR-003-webhooks-firmados-hmac.md) | Webhooks firmados con HMAC-SHA256 | Aceptado |
| [004](ADR-004-checkout-hospedado.md) | Checkout hospedado servido por la pasarela | Aceptado |
| [005](ADR-005-arquitectura-hexagonal.md) | Arquitectura hexagonal con puertos de salida | Aceptado |
| [006](ADR-006-api-key-admin-y-checkout-publico.md) | API key en `/admin` y endpoints públicos dedicados para el checkout | Aceptado (modifica 004) |
